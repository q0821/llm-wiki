# LLM Wiki 讓 Obsidian 升級成自我進化的第二大腦（PAPAYA 電腦教室）

**作者**：[[PAPAYA-電腦教室]]
**平台**：YouTube（`ZC8AI_jFWnU`）
**抓取於**：2026-07-10
**原始連結**：https://www.youtube.com/watch?v=ZC8AI_jFWnU

零技術假設的白話教學。用一個蒐集三國史料的高中生「小杰」當範例，把 [[LLM-Wiki]] 從 Obsidian 基礎操作一路走到 Codex 自動化。是本知識庫第二篇 [[LLM-Wiki]] 教學來源（前一篇為進階向的 [[src-techhanlin-llm-wiki-tutorial]]），走的是**入門操作示範**路線。

## 核心主張

- [[LLM-Wiki]]（[[Andrej-Karpathy]] 提出）的精神：**人類只提供原始資料，AI 負責閱讀、拆解、連結、整合**。維護知識庫最累的不是讀或想，是歸檔（bookkeeping），而 AI 不會無聊、不會忘記更新交叉引用、一次能動十幾個檔案
- 三層資料夾架構：原始資料（只讀不改）→ 知識庫（AI 撰寫維護）→ 指導手冊（規範 AI 行為）
- 這篇的獨特點：**用 [[OpenAI-Codex-CLI|Codex]] 示範**（指導手冊檔名 `AGENTS.md`），並把流程一路推到**排程全自動**

## 詳細摘要

### 一、Obsidian 先備操作（入門層）

影片前半是零基礎 Obsidian 教學，與本知識庫方法論相關的功能：

| 功能 | 操作 | 對應本知識庫概念 |
|---|---|---|
| 屬性面板 | 連打三條橫線 | YAML frontmatter |
| 雙向連結 | 兩個左方括號 | `[[wikilink]]` |
| 範本 | 指定範本資料夾 + 插入模板 | 頁面格式一致性 |
| 反向連結 | 頁面右上角展開 | 連結網路 |
| **未連結但提及** | 反向連結面板下方，按「連結」 | **等於 lint 檢查項 5（缺少交叉引用）的手動版** |
| 附件資料夾 | 設定 → 檔案與連結 | `raw/assets/` 慣例 |
| 關聯圖過濾 | 過濾設定輸入語法 | 排除範本頁等雜訊 |

### 二、三層架構改造

小杰把資料夾改成：
- **史料**（原始資料層）：PDF、網路文章，AI 只讀不改
- **知識庫**（AI 維護層）：人物、事件頁 + **目錄**（列每頁連結與說明）+ **日誌**（每次更新追加、可回溯、避免重複匯入）
- **指導手冊**：Claude Code 用 `CLAUDE.md`，[[OpenAI-Codex-CLI|Codex]] 用 `AGENTS.md`。寫明資料夾用途、工作流程、不准做什麼

> 對照本知識庫：史料=`raw/`、知識庫=`wiki/`、目錄=`index.md`、日誌=`log.md`、指導手冊=`CLAUDE.md`。**幾乎一對一對應。**

### 三、實際流程（Codex 示範）

1. 史料丟進原始資料夾（直接貼上，或用 **Obsidian Web Clipper** 一鍵擷取網頁）
2. Codex 選「使用現有資料夾」指向 vault
3. 下指令「把史料全部匯入知識庫」；過程要核准新檔案，嫌煩可選「**代我核准**」全自動
4. 回 Obsidian 驗收：人物/事件頁照範本產出、雙向連結自動建好、日誌記錄書卷、目錄列出說明、關聯圖擴大

### 四、進階自動化

- **查詢**：先在指導手冊寫規範（回答前先讀目錄定位、答覆標明引用來源），實測題「反董卓聯盟為何沒消滅董卓」
- **健檢**：檢查項寫進指導手冊（失效雙向連結、重複筆記）
- **排程**（Codex 功能）：用講的建立，如「每天早上 9 點檢查史料夾有無新資料」；定期健檢也適合排程（如每週日上午九點）
- **視覺化**：請 AI 把筆記轉成互動式 HTML 資訊圖表（如三國事件時間軸），輸出到根目錄

## 個人吸收（2026-07-11）

> 本段依 [[Ratchet-Pattern]] 的 ingest 個人吸收機制產生。使用者讀「代替影片的長文整理頁」後、建 wiki 頁前 quiz。

**使用者答案**
- Q1（一個重點）：「我們負責提供原始的材料，靠 AI 來整理，有需要查詢什麼的時候再來問 AI。不過這樣的狀況是整理得很好，但是沒有進到腦子裡面。」
- Q2（打算用在什麼場合）：「看看有沒有值得納入目前工作流的機會。」

**LLM 觀察**
- **記住的是反論而非機制，是好訊號**：多數人只會記住「人丟資料、AI 整理、要用再問」的操作機制；使用者把長文頁第 06 節那句「整理得很好但沒進腦」一起記下，抓到的是這篇最有價值的那一層。
- **論點/場合錯位（本次主軸）**：Q1 是一句**警告**（全自動 → 知識不進腦），Q2 卻是「找**可納入**的機會」。影片裡最「可納入」的具體物幾乎都是自動化功能（Codex 排程、代我核准、Web Clipper、未連結批次補），全部往「沒進腦」方向拉。帶著「找機會」的眼睛看，最容易撿走的正是 Q1 在反對的東西。命名為「**警告 vs 採用的自我拉扯錯位**」——使用者的核心洞察與其行動意圖指向相反方向。
- **自我指涉**：使用者這個 wiki 正在跑的 ingest 個人吸收流程（quiz → 逼講重點 → 寫本段），本身就是影片沒做、專門解「沒進腦」的機制。對「要不要納入工作流」，答案不是「再加自動化」，而是「守住已建好的人工關卡」。

**重組路徑建議**
- 納入機會用「**內容類型**」切，不是用「功能好不好用」切：
  - 資料型（規格、清單、流水帳）→ 放心走全自動（Codex 排程／代我核准）
  - 論點型（觀點、框架、方法論，像這篇本身）→ 留人工關卡（個人吸收段）
- 這與 [[Ratchet-Pattern]]、本專案 CLAUDE.md「Ingest 個人吸收段」規則同源；本片是那條規則的**反面教材**（全自動路線的失敗模式具象化）。
- 真正值得評估納入的「新東西」（本 wiki 尚無對應）：Codex 排程式定期 lint（對照 [[Managed-Agents]]）、互動式 HTML 時間軸輸出。Web Clipper 則已被 iCloud inbox 方案取代，不需重複。
