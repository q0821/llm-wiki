# 為自己建一套 Skill／Agent 體系

> 來源：`未命名-20260716-001519.md`（inbox 轉貼，未署名，FB／部落格論述貼文口吻）

## 一句話定位

> **今年 AI 的關鍵字不是「哪家模型最聰明」，而是「你有沒有替自己建構一套 Agent 體系」。** 從「會用聊天介面」升級到「擁有一支只替你打工的 AI 團隊」。

## 核心論述鏈

1. **從會用介面到擁有團隊**：多數人用 AI 還停在「高級搜尋／一問一答」。大廠都在往「協調多子任務」靠攏——OpenAI **Ultra Mode**（並行調度多 agent）、Anthropic **管理者框架**（最強的 [[多模型角色編排\|Fable 5 當管理者]]、便宜的 Sonnet 當執行子 agent）、Cursor **Sand**（桌面級代理指揮各種 coding agent）。收斂到個人＝「每個人都可以擁有一隻自己定義的 AI 團隊」。

2. **為什麼要自己建（三層原因）**：
   - **現成 Agent 不懂你的語境**：專案專用名詞、團隊程式碼架構、你的寫作／設計風格、你對「夠好 vs 不行」的界線——通用 agent 做不到，要靠自建 Skill／Agent 長期投餵。
   - **省的不是打字時間，是判斷時間**：引「自動化真正價值不是減少點擊，而是減少**重複判斷**」。最耗能的是重複溝通（重想同類問題、每次重講背景、反覆手動驗收）。
   - **模型差距縮小時，誰更會設計 Agent 放大差距**：頂級模型（GPT-5.6／Fable 5／Grok 4.5）聰明程度愈來愈接近，勝負轉到「利用上下文、對的 Skill、任務拆解粒度、設計穩定可重用的迴圈」。**大廠卷聰明，我們卷協作。**

3. **怎麼建（三個面向）**：
   - **Skill**：把你已會的事寫成 AI 可重複執行的說明書（固定輸入輸出格式、約束風格邊界、加檢查規則）。起點常是提示詞，加上格式／規則後就趨近 Skill。
   - **Agent**：讓 Skill 串起來——上層 agent 理解目標、拆子任務、選 Skill／工具、控制順序與並行、收集結果做總檢查。（＝Ultra Mode／管理者框架／Sand 在底層做的事，差別是「只替你一人打工」。）
   - **系統**：可長期累積迭代——**放 Git Repo**、文件記錄每次改動原因、最小可用發佈流程（改提示詞 → 專案試跑 → 通過就 commit & push）。

4. **從小事做起**：挑「每週至少做三次」的小任務寫成固定 Skill（不是散落聊天記錄的提示詞）。例：每週部落格／電子報結構化大綱、每次 PR 的 changelog／breaking changes 提醒、每天工作回顧＋隔天三件事。

## 關鍵引用
